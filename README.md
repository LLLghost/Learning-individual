# Серверная инфраструктура

Многостраничный университетский курс для самостоятельного изучения серверной инфраструктуры: Linux, сети, серверное оборудование, хранение данных, автоматизация, контейнеры и firmware.

Публичная версия: <https://server-infrastructure-university-ru.alexghost2011.chatgpt.site/>

## Что внутри

- 34 главы (00–33), сгруппированных в 10 частей, ~95 000 слов;
- 37 академических U-модулей с отдельной теорией, разобранными примерами и самопроверкой T;
- 74 работы практикума (по две на модуль: A — воспроизведение механизма, B — исследование);
- 259 автопроверок: 111 заданий и 37 сценариев по 4 шага, с сохранением прогресса в браузере;
- интервальное повторение слабых тем (2 → 7 → 21 день; ошибка возвращает задание в очередь сразу);
- **вопрос до чтения** в каждой главе: ответ даётся прежде объяснения — попытка ответить до чтения улучшает то, что останется после, и неверная попытка работает не хуже верной;
- **свободное воспроизведение** в конце главы: пересказ по памяти, и только потом сверка со списком тем — узнавание готовых вариантов легче припоминания и завышает ощущение владения темой;
- мини-тренажёр в конце каждой главы (2 вопроса с мгновенной проверкой);
- **калибровка уверенности**: перед каждой проверкой отмечается уровень (догадка / склоняюсь к ответу / знаю), отчёт показывает долю верных внутри каждого уровня и отдельно считает верные догадки;
- **журнал ошибок**: каждый неверный ответ целиком — что выбрано, что верно, с какой уверенностью; повторные ошибки выносятся отдельно;
- **смешанный режим**: задания из разных модулей вперемешку, тема скрыта до проверки;
- офлайн-checker на Python (только стандартная библиотека) для лабораторных заданий;
- приложения: справочник диагностических команд, шаблоны runbook, глоссарий (70 терминов со ссылками на главы), контрольные задания с ключами, аннотированный список первоисточников;
- **справка по терминам**: выделите слово или сочетание в тексте — кнопка «Определение» показывает статью из справочника курса (241 термин) со ссылкой на разбирающую главу;
- личные заметки, цитаты, цветные маркеры с отменой, светлая и тёмная темы;
- **навигация по разделам страницы**: список подтем главы сбоку на широком экране и липкой панелью на узком, с подсветкой текущего раздела;
- **маршрут прохождения** (`/route/`): порядок работы, чек-лист по главам и календарь фактического прогресса;
- **резервная копия** всего локального состояния одним файлом: кабинет, мини-тренажёры, календарь, заметки и настройки чтения.

### Каркас главы

Цели → «Перед началом» (связь с предыдущей темой) → основной текст → разобранный пример → лаборатория → **типичная ошибка мышления** → концептуальное и практическое углубление → лестница самостоятельности → самопроверка → итоги → мини-тренажёр → U-модуль.

Разбор намеренно сломанного стенда (break/fix) сосредоточен в работах **B** практикума и в главе 33 (13 последовательных аварий), а не размазан по всем главам.

### Нумерация: главы, модули и работы

Это единственное место, где легко запутаться. **Номер главы и номер академического модуля — разные шкалы.**

- Главы нумеруются 00–33 и идут по порядку изложения.
- Модули U00–U36 привязаны к темам и идут в том же порядке, но их больше, чем глав: глава 2 содержит два модуля (U01–U02), глава 15 — три (U15–U17), глава 23 — два (U25–U26). Свой модуль есть у каждой главы, кроме нулевой: она ставит стенд и опирается на модуль первой.
- Работы практикума **L** и задания проверки знаний нумеруются **по модулям**. Поэтому L16 (ZFS) относится к главе 15, а L26 (Kubernetes) — к главе 23.

Соответствие не задано вручную: `scripts/build-static.mjs` вычисляет его по тому, внутри какой главы физически находится заголовок U-модуля, а `scripts/validate-site.mjs` проверяет, что все ссылки этому соответствуют. Правка учебника не может незаметно разорвать связку.

## Структура репозитория

| Путь | Назначение |
| --- | --- |
| `public/course.html` | **Исходный учебник целиком.** Единственный источник содержания. |
| `public/reference-terms.json` | Справочник терминов: дополнение к глоссарию и варианты написания для поиска по выделенному тексту. |
| `scripts/build-static.mjs` | Генератор сайта: режет учебник на 79 маршрутов, собирает навигацию, тренажёры, маршрут прохождения, справочник, CSS и JS. |
| `scripts/validate-site.mjs` | Проверка собранного сайта: ссылки, якоря, связка глава↔модуль↔практикум, состав тренажёров. |
| `static-src/index.html` | Обёртка с iframe для предпросмотра. |
| `app/` | Обёртка Next/Vite от шаблона хостинга: iframe с учебником и регистрация инструментов WebMCP. Используется только `pnpm dev`; в сборку сайта не входит. |
| `build/` | Результат сборки, в Git не хранится. |

## Локальный запуск

```powershell
pnpm install
pnpm build
python -m http.server 4175 --bind 127.0.0.1 --directory build
```

После запуска откройте <http://127.0.0.1:4175/>.

## Проверка

```powershell
pnpm validate
node --check build/assets/site.js
```

## Публикация в подкаталоге (GitHub Pages)

По умолчанию сайт рассчитан на корень домена. Для страниц проекта на GitHub Pages,
где адрес выглядит как `https://<владелец>.github.io/<репозиторий>/`, задайте базовый
путь — он подставится во все ссылки, запрос индекса поиска и переходы из учебного кабинета:

```powershell
$env:BASE_PATH = "/Learning-individual"
pnpm build
pnpm validate
```

Маршруты и структура каталогов при этом не меняются, поэтому тот же `build/` можно
опубликовать и в корне: достаточно собрать без `BASE_PATH`. Для личного сайта
(`<владелец>.github.io`) и для своего домена базовый путь тоже не нужен.

Готовый рабочий процесс лежит в `.github/workflows/pages.yml`: он собирает сайт,
прогоняет проверку и публикует результат. Включается в настройках репозитория:
**Settings → Pages → Source → GitHub Actions**.

## Справочник терминов

База собирается на этапе сборки из двух источников и встраивается в `assets/site.js`, поэтому работает офлайн и без запросов наружу:

1. **приложение C учебника** — 70 статей глоссария разбираются из `public/course.html`, так что определения не могут разойтись с текстом;
2. **`public/reference-terms.json`** — 171 термин, которых в глоссарии нет, плюс `aliasesForGlossary` — варианты написания и синонимы для статей глоссария.

Итого 241 статья и около 550 вариантов поиска. Поиск нечувствителен к регистру и «ё», снимает русские падежные окончания и разбирает выделение от самого длинного сочетания к самому короткому, поэтому «page cache» находится раньше, чем «cache», а «маршрутизации» — как «Маршрутизация». Если статьи нет, карточка предлагает близкие термины.

Чтобы добавить термин, допишите объект в `terms` (`t` — термин, `a` — варианты поиска, `d` — определение, `c` — номер главы) и пересоберите сайт. `pnpm validate` проверит, что база встроена и не потеряла ключевые статьи.

## Как учитывается прогресс

Отметка о пройденной теме ставится сама и только по факту:

- **глава закреплена** — мини-тренажёр в её конце решён полностью;
- **модуль сдан** — в учебном кабинете набраны задания модуля и оба последних шага его сценария.

Дата первого зачёта пишется в `server-infrastructure-timeline-v1` и больше не меняется: запись только добавляется, интерфейса правки даты нет. Календарь и чек-лист на странице `/route/` эти данные лишь показывают. Работы практикума автоматической проверки не имеют сознательно — отметка, которую ставишь себе сам, ничего не доказывает; их подтверждение живёт в вашем инженерном репозитории.

По тому же правилу устроены и упражнения без автопроверки. Отметки в свободном воспроизведении («какие темы я вспомнил сам») и отметка «разобрано» в журнале ошибок ставятся вручную и потому ничего не засчитывают и в календарь не идут — они нужны читателю, а не системе. А калибровка, наоборот, подделке не поддаётся: уровень уверенности заявляется до проверки и после результата уже не меняется.

Заметки, результаты проверок и настройки интерфейса сохраняются в `localStorage` текущего браузера и никуда не отправляются. Переносить и резервировать их удобнее всего кнопками на странице `/route/`: одна копия собирает всё состояние сразу.
