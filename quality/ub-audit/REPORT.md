## Открытые находки

### P1 — две вкладки теряют изменения друг друга

Каждая вкладка держит собственную копию всего прогресса и записывает её целиком
в один ключ localStorage. Последняя запись восстанавливает устаревшие поля другой
вкладки. В реальном Chromium: первая вкладка сохраняет заметку урока `why`, вторая
сохраняет заметку урока `request`; первая заметка становится пустой.

Повтор: `npm run build`, затем `node quality/ub-audit/reproduce-two-tabs.mjs`.
Фактический результат сохранён в `logs/two-tabs.json`: `firstNoteLost: true`.
Это известный дефект, а не проходящий регрессионный тест. Пока не использовать
две вкладки для одновременного редактирования. Следующая правка должна определить
единственного писателя либо разнести независимые записи и сохранить конфликты;
просто добавить обработчик события `storage` недостаточно для гарантии.

### P2 — большие функции не удовлетворяют CRAP < 10

Crapper обнаружил 183 функции, из них 15 имеют CC ≥ 10. Даже при полном покрытии
CRAP не ниже CC. Главные точки: `initialize` — 242, `startWorkshop` — 151,
`mountJourney` — 150, `runner.main` — 44, `proxmox_backup.main` — 36.
Это цикломатическая сложность, не измеренный общий CRAP: полное покрытие проекта
не собрано. Вложенные обработчики входят в сложность внешней функции по правилам
инструмента. Нужны выделение состояния и сценариев в небольшие проверяемые части,
затем сохранение прежнего поведения полными браузерными и стендовыми проверками.

### P2 — нет общей оценки силы тестов

Статический scan основной UI/мастерской и двух исполнителей нашёл 952 мутационные
точки. Выполнены все 24 точки трёх новых модулей, а не все 952 исходных точки.
Скан не доказывает убийство мутаций. Данные 100% покрытия относятся только к
`http-json.mjs`, `progress-state.js`, `verify-evidence.mjs`. Браузерное покрытие
остального интерфейса и общее Python-покрытие не измерены.

### P3 — одна пара дубликатов dryer с оценкой 1.00

`runner.atomic` и `proxmox_backup.save` одинаково выполняют атомарную JSON-запись.
Не объединены: оба файла поставляются как самостоятельные скачиваемые
исполнители, общий импорт нарушит этот контракт. Вариант развития — единый
исходный генератор, который встраивает общий код в два самостоятельных файла.
Такое изменение потребует повторной стендовой приёмки новых хешей. Формальное
требование навыка убрать все дубликаты ≥ 0.8 здесь пока не выполнено.

## Непроверенное и границы

- Новый полный прогон чистых Proxmox-ВМ не выполнялся. Исполнители/каталог не
  изменялись; проверены сохранённые доказательства прежней приёмки. WSL не
  заменяет Proxmox. 15 недоступных WSL-работ перечислены в `practice-wsl.json`.
- Реальное ECC/BMC/прошивки/физические носители и обучение человеком не проверены.
- Внешние сайты не обходились; классификация HTTP/сети проверена на фикстуре.
- GitHub Actions локально не запускался: выполнены его команды; удалённая
  публикация и `git push` не выполнялись.
- Старые Linux-worktree действительно существуют в Ubuntu, часть содержит
  незакоммиченные bundle. Ничего не удалено; Windows-пометка prunable не даёт
  основания безопасно чистить их.
- Подозрение на гонку при захвате устаревшего `owner.lock` осталось результатом
  чтения кода, без воспроизведения. Не представляется подтверждённым дефектом.

Порядок дальнейшей работы: сначала писатель прогресса и конфликт вкладок, затем
декомпозиция трёх крупнейших функций с проверками поведения; после этого расширять
покрытие и мутационные прогоны. Переписывать стендовые исполнители только вместе
с повторной приёмкой их новых версий.
