# Живая приёмка лаборатории, 28 октября 2026

Проверена текущая инфраструктурная редакция курса на Proxmox `10.30.90.35`.
Это авторская автоматизированная приёмка: подготовка, решение, проверка,
импорт отчёта, откат и повтор. Она не доказывает самостоятельность ученика.

Проверенный коммит исполнителей: `be38fc1fd8c22c9884e2f5cca094b97cb935a3c0`.
Пять SHA содержания, сборщика, проверки, практики и упакованного исполнителя —
в `run-meta.json`. Более поздний коммит добавляет протоколы и проверки выпуска,
не переносит приёмку на изменённые задания или исполнители.

## Среда и порядок

VM9200 (.20) — приложение и DNS, Debian 12 / 6.1.0-54-amd64, 4 vCPU,
6 GiB, OVMF, два виртуальных NUMA-узла. VM9201 (.21) — клиент и мониторинг;
VM9202 (.22) — отдельное хранилище копий, по 1 vCPU / 1 GiB.
Адреса находятся в `172.30.253.0/24`, на существующем `mayakbr0`.
Управление Proxmox и его NAT не переделывались.

9200 — полный клон 9100 со снимка `mayak-clean-dependencies`; 9201/9202 —
клоны чистого backup-источника. Идентификаторы машин и SSH host keys заменены.
После замены machine-id выполнена настоящая холодная загрузка. Исходные
9100/9101 и их снимки сохранены, сами исходные ВМ остановлены из-за бюджета ОЗУ.
Конфигурации, наблюдения платформы и финальное состояние — в JSON/TXT рядом.

Сначала выполнены 45 сценариев и native backup с текущим исполнителем.
Затем сквозная работа: между вариантами все три узла возвращались к снимку
`mayak-infrastructure-base`, использовались разные данные и TLS-порты.
После всех откатов отдельно выполнены девять прежних лабораторных.
Для L12B в свободный SCSI-слот добавлен новый пустой диск с явной серией
`MAYAK-LAB-EMPTY`; существующие диски не заменялись. Для прежних работ
установлены chrony и tracepath. Сходимость NTP и drift получены от реального
chronyd; подготовленный ответ вместо измерений не использовался.

## Что проверяет сквозная работа

Три ВМ работают как система: JSON-инвентаризация оборудования, DNS,
TLS с проверкой доверенного CA и имени, отдельный пользователь приложения,
фильтрация доступа к порту, systemd-службы и таймер мониторинга.
Повторное применение конфигурации ничего не меняет и сохраняет PID службы.
Неверный CA, неверное TLS-имя и обращение с неразрешённого узла отклоняются.

В каждом варианте внесены и обнаружены: остановка процесса, сетевая блокировка,
неверная запись DNS, неправильные права на данные, удаление данных и подмена
содержимого при HTTP 200. После исправления клиент проверяет точный SHA данных.
Два последних случая восстанавливаются из копии, реально вынесенной на Windows
и возвращённой обратно. Клиент фиксирует отказ службы мониторинга.

Полный архив ВМ создаётся vzdump; исходная VM9200 останавливается, архив
восстанавливается в VM9203, и внешний клиент проверяет DNS/TLS/содержимое.
После проверки удаляется только клон с точной меткой владельца; исходная ВМ
запускается снова. История конфигурации сохраняется в Git, приватные ключи туда
не добавляются. Временные VM100/101 native backup также удалены с дисками.

## Найденные проблемы и исправления

Первый проход 45 сценариев дал 41/45. Причины сохранены в guest-first-run.json:
журнал после замены machine-id без перезагрузки, неуказанный закреплённый kind
image и незагруженный dm_multipath. Исправлена подготовка, затем все 45 пройдены
заново. Модули zfs/dm_multipath загружаются после холодного старта.

Обнаружен дефект исполнителя: shell наследовал BASH_ENV и читал профиль SSH,
который при nounset выдавал PS1: unbound variable. Реальные Linux-тесты сначала
показали два отказа, после исправления — два успеха. Исполнитель очищает
BASH_ENV/ENV и запускает bash с --noprofile --norc. После коммита be38fc1
повторены все 45 × 2, а не только упавшие сценарии.

Два первоначальных сквозных прогона остановились: синтаксис правила nft и
строгая проверка владельца клона при URL-кодировании description в qm config.
Добавлены nft -c и декодирование перед точным сравнением; защита не отключалась.
Неуспешные протоколы integration-20261028-091432.json / -091916.json сохранены.
Итоговый успешный прогон: 20261028-093009. Старый архив перемещён только после
сверки SHA, карта retained-backup-map.json сохранена.

## Воспроизведение и ограничения

`npm run validate:release` проверяет текущие SHA, архивы, 110 отчётов,
полноту сквозного протокола и браузерное поведение. Для подкаталога задать
BASE_PATH=/Learning-individual, затем вернуть обычную сборку.
Проверка сохранности протоколов — не новый удалённый прогон и не цифровая подпись.
Код авторского прогона в harness/ — это доказательство конкретного стенда,
с фиксированными VMID и путями. Не запускать без новой проверки владельцев
и свободных ресурсов; для повторения копировать в work/stand-2026-10-28.
Приватные ключи оператора/CA и полные архивы ВМ в этот каталог не включены.

Непроверено: самостоятельное прохождение человеком и перенос навыка после
перерыва; физические ECC/BMC/питание/прошивки/HBA и настоящая аппаратная NUMA.
OVMF/NUMA виртуальные. Все три ВМ на одном Proxmox — это не испытание HA.
Полные архивы ВМ остались в закрытом каталоге Proxmox; вынос за пределы хоста
доказан для данных приложения, а не для полного восстановления после гибели
Proxmox. Сеть VLAN/маршрутизация проверена отдельными изолированными сценариями,
не физической стойкой. Известный P1 перезаписи заметок двумя вкладками остаётся.
