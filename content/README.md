# content/ — исходники учебника

Единственный редактируемый источник книги. `public/course.html` (переносимый
однофайловый учебник) и сайт в `build/` собираются из этого каталога и второй
редактируемой копией не являются.

## Сборка

```bash
npm run build      # content/ → public/course.html + сайт в build/
npm run assemble   # content/ → public/course.html (без сайта)
```

`npm run validate` проверяет, что `public/course.html` совпадает со сборкой
`content/`: правка фрагмента без пересборки падает проверкой «устарел».
Коммитьте фрагмент и пересобранный `course.html` одним коммитом.

## Карта содержания

Порядок файлов в `content/manifest.json` — порядок сборки книги; он же
порядок разделов на сайте. У каждого фрагмента `start` задаёт, где он
начинается в собранном документе, а необязательный `anchor` — идентификатор,
который обязан встречаться в нём ровно один раз.

| Фрагменты | Что это | Куда попадает на сайте |
| --- | --- | --- |

## Как править текст

- **Проза уроков, глав и приложений** — правится прямо во фрагменте либо
  инструментом вычитки `node scripts/text-nodes.mjs` (он сам разложит правки
  по фрагментам). Заголовок или раздел добавили — прогоните
  `node scripts/text-nodes.mjs synctoc`: оглавление в `shell/sidebar.html`
  собирается из заголовков.
- **Банк заданий** (`data/study-data.html`) — только через
  `node scripts/study-strings.mjs`: блок сериализован с точными
  разделителями, прямая правка ломает форматирование и ответы.
- **Стили и клиентский JS сайта** — не здесь: они шаблонные строки в
  `scripts/build-static.mjs` (см. CLAUDE.md). Стили и скрипт самой
  однофайловой версии — `shell/style.html` и `shell/course-script.html`.

После правки: `npm run build`, затем `npm run validate`. Оба режима — с
`BASE_PATH` и без (см. README).

## Как добавить главу

1. Создайте `content/chapters/chapter-NN.html` с `<h1 id="bNN">…</h1>`.
   Если глава открывает новую часть, файл начинается с её заголовка `<h1>`
   (как `chapter-01.html` начинается с «Часть I») — заголовок части уезжает
   на страницу своей первой главы, отдельной страницы у части нет.
2. Впишите фрагмент в `content/manifest.json` между соседними главами:
   `start` — маркер заголовка части или самой главы, `anchor` — `"bNN"`.
3. Обновите производные места (они не выводятся из фрагментов автоматически):
   `parts` в `scripts/build-static.mjs`, вопросы `chapter-quick-data`
   (`data/chapter-quick-data.html`), работу практикума `lab-NN` при новом
   модуле, число маршрутов в `scripts/validate-site.mjs`, оглавление
   (`synctoc`), недельный план в предисловии и подписи в `CHANGELOG.md`.
4. `npm run build && npm run validate` — сборка сама откажется работать,
   если маркер главы не найден или попал не в тот фрагмент.

Тот же порядок — для урока (`lessons/lesson-07.html`, якорь `start07`) и
работы практикума (`practice/lab-37.html`, якорь `lab37`): манифест — источник
порядка, сборка режет страницы по маркерам, валидатор сверяет состав.

## Чего здесь делать нельзя

- Не правьте `public/course.html` руками — файл собирается из `content/`, и
  любая ручная правка будет отклонена проверкой устаревания.
- Не меняйте порядок фрагментов в манифесте произвольно: порядок блоков —
  часть контракта сборки (см. «Архитектура» в CLAUDE.md), его перестановка
  ломает нарезку сайта молча.
- Не заводите HTML-файл в `content/` без записи в манифесте — сборка
  откажется работать, пока файл не внесён (или не убран).
