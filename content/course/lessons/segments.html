Разделить сеть на наблюдаемые сегменты

Результат: Проверить принадлежность двух интерфейсов одному VLAN.

Часть общей системы: Разделение сети и управляемые пути между сегментами.

Что сохранить в инженерном журнале: Карта VLAN или мостов с точками маршрутизации.

Разберёмся до действия

VLAN разделяет домены второго уровня. Метка VLAN в кадре и IP-префикс решают разные задачи: одинаковый IP-префикс не соединяет раздельные VLAN. Мост пересылает кадры между разрешёнными портами; trunk должен пропускать нужные метки на всём пути. Для связи разных IP-подсетей используют маршрутизацию и подходящую политику. LACP объединяет линии, но обычный поток обычно попадает на одну линию по хешу. Один общий коммутатор остаётся общей точкой отказа.

Среда и права: В учебном Linux-госте обычным пользователем; sudo требуется только для явно указанных изменений. Данные примера можно разбирать без стенда.

Разобранный пример

Команды примера; переменные WORK и NS задаются в инструкции практики ниже:

sudo ip -n "$NS-a" -d link show vlan10
sudo ip -n "$NS-b" -d link show vlan10

Ожидаемый результат: Оба интерфейса имеют VLAN ID 10. Только после назначения второго адреса появляется проверяемая связь в учебной подсети.

Сопоставь наблюдение с описанным механизмом. Вывод относится к проверенному объекту и условиям опыта.

При отклонении: При несовпадении результата сохрани фактический вывод, проверь предпосылки и остановись перед дальнейшими изменениями. Не подменяй наблюдение ожидаемым текстом.

Прогноз и опыт с поддержкой

Подготовь segments. Предскажи результат без адреса узла b, затем назначь 198.51.100.2/24 его vlan10. Подтверди метку и обмен между 198.51.100.1 и .2.

C08-0: Чем различаются роли VLAN, моста, маршрутизатора и межсетевого экрана?

Чёткое разделение ролей снимает значительную часть путаницы: можно иметь два VLAN, прекрасно маршрутизируемых между собой, и мост вообще без адреса. Применение к описанным условиям: VLAN делит домены второго уровня, маршрутизатор связывает сети IP.

VLAN делит домены второго уровня, маршрутизатор связывает сети IP, мост соединяет интерфейсы. Разделение ролей снимает значительную часть путаницы. Применение к описанным условиям: Да: он работает на втором уровне, адрес ему не нужен.

C08-1: Между двумя VLAN нет связности. Почему это само по себе не дефект настройки VLAN?

Отсутствие связи может быть вызвано отсутствующим маршрутом, выключенной пересылкой, политикой экрана или трансляцией адресов — четырьмя разными причинами, ни одна из которых не «неправильный VLAN». Применение к описанным условиям: VLAN по определению разделяет широковещательные домены.

C08-1b: VLAN и адреса настроены по карте, но маршрутизация между IP-подсетями ещё не проверена. Что проверить для связи между ними?

Проверь применимые маршруты, включённую пересылку, разрешения фильтра и обратный путь. Отсутствие связи не доказывает один конкретный дефект VLAN и не означает, что любой отказ связи ожидаем. Применение к описанным условиям: Отсутствие маршрута, пересылки, разрешения экрана.

L08A#why: Клиенты подключены к разным VLAN одного коммутатора, а маршрутизация между подсетями не настроена. Почему прямой связи нет?

VLAN делит один коммутатор на несколько независимых коммутаторов. Соединить их — работа маршрутизации, а не настройки портов; поэтому «сделайте им один VLAN» и «поставьте маршрутизатор» — решения с разными последствиями для изоляции. Применение к описанным условиям: Потому что VLAN — это разделение на втором уровне.

Углубление: Граница Ethernet и граница политики

Граница Ethernet и граница политики

VLAN разделяет широковещательные домены Ethernet. Тег 802.1Q передаёт номер VLAN на конкретной линии; нетегированный кадр получает VLAN по настройке порта. PVID определяет классификацию такого входящего кадра, trunk переносит разрешённые VLAN. Изоляцию создаёт настройка коммутатора или моста, а не сам факт наличия числа в кадре. Linux bridge учит MAC и пересылает кадры; маршрутизатор пересылает IP между сетями.

Network namespace имеет собственные интерфейсы, маршруты и сокеты. Veth соединяет два конца виртуальной линии. Bond объединяет интерфейсы по выбранному режиму; LACP согласует агрегирование со switch, но один поток обычно ограничен выбранным хешем одним участником. NAT меняет адреса/порты и не заменяет разрешающую политику; forwarding должен быть включён отдельно. Виртуальный мост и физический trunk нужно сопоставить по всему пути.

Другие условия: разобранный случай

Даны наблюдения: ВМ отправляет нетегированный трафик, порт моста назначает VLAN 20, uplink разрешает только VLAN 10.

Разбор: Кадр классифицирован в VLAN, который не проходит uplink. Связь с самим хостом может при этом работать и не подтверждает путь до шлюза.

Это учебные данные, а не протокол выполненного действия.
