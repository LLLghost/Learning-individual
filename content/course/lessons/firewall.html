Отличить маршрутизацию от разрешения трафика

Результат урока: Отличить маршрутизацию от разрешения трафика и подтвердить вывод наблюдением.

Сначала разберёмся

Маршрут выбирает путь, а межсетевой экран решает, какой трафик разрешён. NAT меняет адреса или порты, но сам по себе не заменяет разрешение пересылки. Правила читают вместе с цепочкой, направлением, состоянием соединения и счётчиками.

Разобранный пример

Пакет доходит до маршрутизатора, но не выходит к серверу. Нужны счётчик подходящего правила и наблюдение на обоих интерфейсах.

Где и от чьего имени: На учебном router с sudo только прочитай правила и сопоставь их с адресами одного запроса.

Цель команды: получить наблюдение, описанное ниже. Команды с sudo требуют прав администратора учебной ВМ; остальные выполняются обычным пользователем.

sudo nft list ruleset

Ожидаемый результат: Правила и счётчики nftables. Это описание вида результата; имена и значения сверяют со своей машиной.

Если результат отличается: сохрани вывод и код ошибки, проверь имя машины, наличие инструмента и права. До выяснения причины не переходи к изменяющим действиям.

8.7. Межсетевой экран как набор точек подключения и правил

Современный Linux обычно использует nftables, хотя совместимость с iptables всё ещё встречается.

Посмотреть набор правил:

nft list ruleset

При диагностике важно понимать направление пакета:

packet to local host       → input path
packet created locally     → output path
packet routed through host → forward path

Если правило межсетевого экрана находится в forward, оно не обязательно влияет на сервис, слушающий на самом маршрутизаторе.

8.8. Межсетевой экран с состоянием и conntrack

Межсетевой экран может учитывать состояние соединения. Упрощённая политика:

allow established/related
allow explicitly permitted new traffic
drop остальное

Conntrack хранит состояние потоков. Это важно при NAT и асимметричной маршрутизации: если запрос и ответ проходят через разные устройства с состоянием, одно из них может не видеть ожидаемого состояния соединения.
