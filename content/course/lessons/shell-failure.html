Обрабатывать отказ команды и ограничивать ожидание

Результат урока: Обрабатывать отказ команды и ограничивать ожидание и подтвердить вывод наблюдением.

Сначала разберёмся

Скрипт должен различать успешный результат, отказ и превышение времени ожидания. set -e имеет исключения в зависимости от контекста команды и не заменяет явную обработку ожидаемых ошибок. timeout ограничивает ожидание; его код завершения нужно трактовать по документации выбранной версии.

Разобранный пример

Команда проверки может штатно вернуть ненулевой код при отсутствии объекта. Это нужно обработать как состояние задачи, сохранив диагностику.

Где и от чьего имени: В домашнем каталоге запусти безопасное ожидание с коротким пределом и сравни коды двух случаев.

Цель команды: получить наблюдение, описанное ниже. Команды с sudo требуют прав администратора учебной ВМ; остальные выполняются обычным пользователем.

timeout 5s sleep 1; printf "%s\n" "$?"

Ожидаемый результат: Код 0 при завершении до ограничения. Это описание вида результата; имена и значения сверяют со своей машиной.

Если результат отличается: сохрани вывод и код ошибки, проверь имя машины, наличие инструмента и права. До выяснения причины не переходи к изменяющим действиям.

Практическое углубление: Скрипт диагностики должен быть безопасным по умолчанию

У рабочего диагностического инструмента есть требования, которых нет у одноразовой команды из истории оболочки:

  • по умолчанию только чтение;
  • явные ограничения по времени;
  • отсутствие зависания на одном недоступном устройстве;
  • поток ошибок не теряется;
  • код возврата отражает результат;
  • в выводе есть время и имя хоста;
  • чувствительные данные не попадают в отчёт случайно;
  • разрушающий режим, если он вообще существует, включается отдельным флагом.

Поэтому хороший скрипт оболочки начинается не с количества grep, а с контракта: что он читает, что изменяет, какой вывод обещает и как сигнализирует о частичном отказе.
