Установить инструмент и узнать происхождение файла

Результат: Установить происхождение исполняемого файла и версию пакета, который его поставил.

Объект: Системный /usr/bin/python3 в Debian 12/13-госте.

Часть общей системы: Происхождение программ на управляемой системе.

Что сохранить в инженерном журнале: Версия инструмента и пакет — владелец файла.

Разберёмся до действия

Пакет объединяет файлы программы и сведения о зависимостях. В Debian apt получает пакеты из настроенных репозиториев, а dpkg хранит сведения об установленном составе. Имя программы в PATH не всегда указывает на ожидаемый файл: локальная копия может заслонить системную. Версия пакета и версия запущенного процесса тоже могут различаться после обновления без перезапуска. Проверка происхождения начинается с фактического пути и записи пакетной базы, а не со скачивания случайного установочного сценария.

Среда и права: Чтение пакетной базы обычным пользователем; установка отсутствующего python3 через sudo apt install python3 на выделенной ВМ.

Разобранный пример

Команды примера; переменные WORK и NS задаются в инструкции практики ниже:

command -v python3
dpkg-query -S /usr/bin/python3
dpkg-query -W -f='${Package} ${Version}\n' python3-minimal

Ожидаемый результат: Первый вывод показывает найденный путь. В Debian /usr/bin/python3 принадлежит python3-minimal; последняя команда печатает установленную версию пакета. Номер зависит от выпуска ОС.

dpkg-query связывает конкретный файл с установленным пакетом. Это ещё не проверка всех байтов файла и не доказательство того, что служба использует именно этот интерпретатор.

При отклонении: Не подменяй официальный репозиторий ради совпадения номера версии. Отсутствие записи в dpkg — наблюдение о происхождении, а не автоматический признак вредоносности.

Прогноз и опыт с поддержкой

Предскажи путь Python. Выполни три чтения. Если Python отсутствует, сначала прочитай план apt install, затем установи его внутри гостя. Сохрани владельца и версию в observation.txt по инструкции практики.

Самостоятельная задача

Найди путь другой уже установленной программы и пакет-владелец. Если команда — встроенная функция оболочки или локальный файл, объясни, почему dpkg-query может не найти владельца.

Объясни и вернись позже

Какие дополнительные действия нужны после обновления пакета работающего сервиса? Через день восстанови происхождение программы по её абсолютному пути.

Свободное объяснение сохраняется для самопроверки; автоматическая проверка не оценивает его смысл.

Первоисточник для сверки поведения и версии: документация. Команды Linux рассчитаны на Debian 12/13; доступность конкретной функции проверяется предпосылками работы.

Углубление: Пакет — управляемый набор файлов

Пакет — управляемый набор файлов

Пакет содержит файлы, метаданные, зависимости и действия установки. Репозиторий публикует версии и подписанные сведения, по которым менеджер проверяет происхождение и целостность. Доверие к подписи не доказывает отсутствие ошибок в программе. apt выбирает версии и разрешает зависимости; dpkg учитывает установленные Debian-пакеты.

Исполняемый файл в PATH может происходить из пакета, локальной установки, виртуального окружения или пользовательского каталога. Поэтому сначала устанавливают фактический путь, затем владельца файла и версию. Обновление списка пакетов отличается от обновления установленной системы. Конфигурация, данные службы и кеши имеют другой жизненный цикл, чем бинарные файлы пакета.

Другие условия: разобранный случай

Даны наблюдения: В пакете установлен один Python, но команда python3 запускает файл из домашнего каталога.

Разбор: Версия пакета не описывает фактически вызванную программу. Причина может быть в порядке PATH, а не в неисправной установке.

Это учебные данные, а не протокол выполненного действия.
