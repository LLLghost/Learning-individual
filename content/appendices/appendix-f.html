Приложение F. Как проверять свои знания

F.1. Пять уровней вопроса

Для каждой темы задавайте себе пять разных вопросов.

1. Термин

Что такое multipath?

Это минимальный уровень.

2. Механизм

Как два пути SCSI превращаются в одно блочное устройство?

3. Предсказание

Что увидит Linux, если multipathd выключен, но оба пути доступны?

4. Диагностика

Приложение зависает при отказе одного пути. Какие измерения разделят переключение хранилища и тайм-аут приложения?

5. Проектирование

Как изменить топологию, мониторинг и тайм-ауты, чтобы отказ одного пути не влиял на приложение?

Настоящее инженерное владение начинается примерно на уровнях 3–5.

F.2. Метод «объясни без команды»

Если можете объяснить проблему только так:

«я выполню ip r, потом ping, потом tcpdump»

попробуйте повторить объяснение вообще без названий утилит:

«сначала определю, какой следующий узел выберет ядро; затем проверю, разрешается ли его адрес второго уровня; затем посмотрю, покидают ли пакеты интерфейс и возвращаются ли ответы».

После этого команды становятся естественным выбором инструментов измерения.

F.3. Метод предсказания результата

Перед нажатием Enter запишите ожидаемые варианты:

Command: ip route get 10.20.30.40

A: via 10.20.0.1 dev eno1
   → route существует и идёт через expected gateway.

B: unreachable
   → routing layer уже объясняет failure.

C: via unexpected interface
   → investigate policy/more-specific route.

Так диагностика превращается в эксперимент.
