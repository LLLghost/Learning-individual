# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Что это

Учебник по серверной инфраструктуре: один исходный файл `public/course.html` (~2 МБ, ~120 000 слов на русском) и генератор без зависимостей, который режет его на статический многостраничный сайт в `build/` (47 маршрутов). Всё остальное — навигация, поиск, тренажёры, учебный кабинет, CSS и JS — вычисляется из этого файла при сборке.

**Язык проекта — русский.** Текст учебника, интерфейс, сообщения и комментарии в коде — по-русски. Комментарии объясняют «почему так», а не «что делает строка»; такой стиль выдержан во всех скриптах, следуйте ему.

## Команды

```bash
node scripts/build-static.mjs          # сборка в build/ (pnpm build)
node scripts/validate-site.mjs         # проверка собранного сайта (pnpm validate)
BASE_PATH=/Learning-individual node scripts/build-static.mjs   # для GitHub Pages в подкаталоге
node --check build/assets/site.js      # синтаксис сгенерированного клиентского JS
python3 -m http.server 4175 --directory build   # посмотреть результат
```

Сборка и проверка используют только стандартную библиотеку Node — `pnpm install` для них не нужен. **Всегда прогоняйте проверку в обоих режимах**: без `BASE_PATH` и с ним, потому что ошибки в ссылках проявляются только во втором.

Инструменты правки исходника (оба физически не могут повредить разметку и ответы — они не отдают то, что нельзя менять):

```bash
node scripts/text-nodes.mjs list [--latin] [--from N] [--limit N]  # текстовые узлы прозы
node scripts/text-nodes.mjs apply patch.json                       # вернуть правки по индексу
node scripts/text-nodes.mjs synctoc                                # пересобрать оглавление
node scripts/study-strings.mjs list [--latin]                      # видимые строки банка заданий
node scripts/study-strings.mjs apply patch.json
```

### Тестов нет — есть `validate-site.mjs`

Отдельного тестового прогона в проекте нет: `scripts/validate-site.mjs` (~670 строк) и есть спецификация. Выбрать одну проверку нельзя, но убедиться, что она работает, можно и нужно так: **сломать вход и увидеть именно её сообщение**, потом восстановить. Так проверялось каждое добавленное правило; добавляя новое, делайте так же.

## Архитектура

### Один источник, всё остальное производно

`build-static.mjs` не разбирает HTML деревом. Он находит границы по идентификаторам: `marker('b07')` ищет `id="b07"` и отступает назад до `<`. Регионы идут в исходнике подряд и режутся срезами:

```
title … start-part → уроки start01–start05 → b00 … b33 → b33-s044 (приложения)
  → selftest → study-app → assessment → labs (lab00–lab36) → assessment-reference
```

Отсюда следует главное: **порядок блоков в `course.html` — часть контракта.** Перестановка региона ломает срезы молча, потому что сборка всё равно пройдёт.

Массив `pages` — реестр «что попало на страницы». Из него строится `idToUrl`, а `rewriteLinks` превращает внутрикнижную ссылку `href="#b07-s003"` в `href="/chapters/07/#b07-s003"`. Раздел, не попавший в `pages`, теряет все ведущие к нему якоря.

### Двойная нумерация

Главы `bNN` (00–33) и академические модули `UNN`/`id="chNN"` (00–36, всего 37) — **разные шкалы**. Работы практикума `LNN` и задания кабинета нумеруются по модулям, не по главам: L16 (ZFS) относится к главе 15, L26 (Kubernetes) — к главе 23. Соответствие нигде не записано руками: `moduleChapter` вычисляется по тому, внутри какой главы физически лежит заголовок модуля, а валидатор проверяет, что все ссылки «Теория» этому соответствуют.

Вводные уроки `/start/01–05` намеренно живут **вне** нумерации глав: своя шкала, свой раздел, свой боковой список. Так их можно было добавить, не сдвинув ни одного идентификатора из 34 глав и банка проверок.

### CSS и клиентский JS живут внутри генератора

Стили и весь браузерный код — шаблонные строки в `build-static.mjs`, попадающие в `build/assets/site.css` и `site.js`. Отдельных файлов стилей нет: правка оформления или поведения сайта — это правка генератора. Сборка клиентский JS **не разбирает**, поэтому синтаксическая ошибка в нём проходит и сборку, и (частично) проверку — валидатор специально прогоняет код кабинета через `new Function`.

### Практика и проверка — одна страница

Работы практикума **не имеют своих страниц**: их текст лежит скрытыми секциями `<section data-lab-module="N">` на `/assessment/`, и вид модуля показывает нужную копией узла (`cloneNode`) — кабинет по-прежнему не собирает разметку из строк. Адрес работы — `/assessment/?module=N`. Раньше это были 37 отдельных страниц, и читатель ходил между практикой и проверкой сам.

Страница практики несёт только работу: вступление, кабинет и ничего после него. Вся справка — критерии освоения, границы автоматической проверки, требования к стенду, контракт сдачи — живёт в разделе `#how-checks-work` на `/about/`, и ссылка из кода кабинета на `#autopractice` подставляется с `BASE_PATH` (`studyScript`). Общее введение практикума (`id="labs"`) **не принадлежит нулевой работе**: вид модуля показывает секцию целиком, поэтому заголовок всего практикума уезжал бы в U00 — он нарезается отдельным срезом `labsIntro`.

### Автопроверка работ практикума

Работа готовится скриптом, читатель решает, скрипт собирает факты в `lab-report.json`, кабинет сверяет и выносит вердикт. В книге это три вещи: `<script type="application/json" id="lab-code-data">` (сам `course_lab.py`), `id="lab-data"` (ожидаемые значения **хешами** и вопрос о механизме) и вид модуля в коде кабинета.

Виды работ: `dataset` — стенд не нужен, скрипт выдаёт данные; `collect` — скрипт только собирает факты со стенда, ничего не ломая; `stand` — скрипт вносит инцидент по случайному зерну и умеет откат.

**Сверка описана данными, а не кодом под каждую работу:** в `checks` перечислены операции из `LAB_OPS` (`hash`, `sameAsClaim`, `matchesClaim`, `offset`, `equals`, `isTrue`…). Добавить работу — значит добавить запись в `lab-data` и пробник в скрипт, а не написать ещё одну почти такую же функцию. Там, где верное значение зависит от стенда (серийный номер диска, размер тома), сверка **относительная**: заявленное сравнивается с измеренным, а не с зашитым ответом.

Сверка идёт в браузере, а не в скачанном скрипте: иначе ожидаемые значения уезжают к читателю вместе со скриптом. Хеш прячет ответ от чтения исходника, но не от перебора — это защита от подглядывания, а не от подделки, и обещать большее нельзя: файл отчёта лежит на машине читателя. Подделка при этом требует знать внесённый вариант и вид подтверждённой гипотезы, то есть почти всё решение.

**Страница кабинета собирается из перечисленных блоков, а не из сплошного среза:** `${studyData}${checkerData}${labCode}${labData}${studyScript}`. Новый блок данных надо назвать в генераторе явно, иначе он просто не доедет до страницы — сборка и разметка при этом останутся правильными.

### Три проверки, и каждая своя

Курс проверяет читателя трижды, и ярусы **не должны пересекаться**:

1. **Мини-тренажёр главы или урока** — сразу после чтения, два вопроса о главных утверждениях: прочитано и понято. Вопросы лежат в `chapter-quick-data` (34 главы) и `lesson-quick-data` (5 вводных уроков) в `course.html`; у главы это вопрос о её модели и вопрос о её «типичной ошибке мышления». Разметку обоих делает одна функция `quickTrainer`, ключ отметки в календаре — номер главы или `sN` для урока: шкалы разные и пересечься не должны.
2. **Задания модуля в кабинете** — позже и по расписанию повторения: применение механизма к незнакомой ситуации, второй ярус, расчёт, сценарий. Только этот ярус идёт в зачёт.
3. **Работа практикума** — на стенде, где готового решения нет.

Раньше первый ярус брал два первых задания модуля **прямо из банка кабинета** (`items.filter(module).slice(0, 2)`): читатель отвечал на оцениваемое задание заранее и вместе с разбором. В разметке это не видно — вопросы там настоящие, просто чужие. Валидатор сравнивает тексты вопросов обеих проверок и не пропускает совпадение.

`chapter-quick-data` лежит **после `</main>`**, рядом с `study-data`, то есть вне всех срезов регионов. Блок с типом (`type="application/json"`) не ломает `followingScript`: тот ищет ровно `<script>` без атрибутов.

### Лаборатория главы и работа практикума — разные ярусы

«Лаборатория» в главе закрепляет **нормальную настройку** механизма; развёрнутая работа `LNN` уводит за пределы готового решения. В шести поздних главах (24, 27–32) работа была написана копией лаборатории: читатель делал одно и то же дважды, и перекрытие по словам доходило до 58%. Лаборатория этих глав сокращена до подготовки и наблюдения, а измерения, отрицательные тесты и инциденты оставлены работе; в конце лаборатории стоит явная ссылка на неё.

### Банк заданий

`<script type="application/json" id="study-data">` в `course.html`: 111 заданий (`items`) и 37 сценариев (`cases`), каждое привязано к модулю. Блок сериализован с разделителями `", "` и `": "`; `study-strings.mjs` воспроизводит это форматирование посимвольно и отказывается работать, если не смог. Правьте банк только через него — прямая правка легко ломает и форматирование, и ответы.

### Прогресс подделать нельзя — это осознанное решение

Задание засчитывается, только когда верны **и ответ, и рассуждение** (второй ярус спрашивается всегда и до вердикта). Уровень уверенности заявляется до проверки и после результата не меняется. Даты в `server-infrastructure-timeline-v1` только добавляются. Всё, что читатель отмечает себе сам — темы в свободном воспроизведении, «разобрано» в журнале ошибок, работы практикума, — **ничего не засчитывает и в календарь не идёт**. Не добавляйте кнопку «отметить пройденным»: это прямо противоречит замыслу.

Состояние хранится в `localStorage` (9 ключей `server-infrastructure-*`). Любой новый ключ обязан попасть в `BACKUP_KEYS`, иначе перенос в другой браузер потеряет часть работы молча — валидатор это проверяет. Один из ключей — `place-v1`, место чтения: адрес, заголовок, ближайший раздел и доля прочитанного. Пишется на страницах с прозой не чаще раза в секунду, читается только главной; адрес из хранилища перед подстановкой в ссылку проверяется, чтобы чужая запись не стала ссылкой куда угодно.

## Что сломается незаметно (и потому закреплено проверками)

Валидатор ловит именно те дефекты, которые не видны ни в сборке, ни в разметке. Прежде чем спорить с ним, прочитайте комментарий рядом с правилом — там записан случай, из-за которого оно появилось.

- **Изменили заголовок или добавили раздел** → `node scripts/text-nodes.mjs synctoc`, иначе оглавление разойдётся с текстом.
- **Добавили или убрали страницу** → в валидаторе зашито ожидаемое число маршрутов (47).
- **Списки markdown внутри `<p>`** (`- пункт` с новой строки) браузер схлопывает в одну строку; в разметке это незаметно.
- **Уровни заголовков** не перепрыгивают ступень, страница не кончается заголовком без текста, навигация по разделам совпадает с `h2` по составу и порядку.
- **Раскладка**: ширина страницы задана через `--page` (её же использует верхняя панель), ширина строки — через `width:min(100%,900px,var(--reading-measure))` (не `max-width`: иначе текст не замечает узкой колонки и уезжает под рейл), рейл разделов встаёт сбоку не раньше 1500px, `hyphens:manual` (автоперенос рвёт обычные слова ради плотности строки).
- **Приложение A**: разделы A.1–A.24, и у каждой команды, меняющей состояние, в её разделе стоит «Осторожно». Справочник читают наискось.
- **Позиция верного варианта**: добавляя задание, не ставьте верный ответ первым по привычке. Один раз так собрался весь банк — и все 74 задания, все вторые ярусы и все 148 шагов сценариев проходились выбором первого варианта. В разметке это не видно; распределение закреплено проверкой.
- **Недельный план** в предисловии — единственное место, где курс разложен по времени. Он уже расходился с книгой: таблица осталась на 28 позициях старой нумерации, когда модулей стало 37. Проверка требует, чтобы все 37 модулей стояли в плане ровно по разу.
- **Мост «глава → модуль»**: строка «Академическое продолжение этой главы: UNN» должна называть ровно те модули, которые физически лежат внутри главы. При двойной нумерации это единственная подсказка читателю, а расхождение в разметке невидимо.
- **Обращение**: книга говорит читателю «вы» — не только местоимениями. Команды («создай», «переходи дальше») и глаголы второго лица («пока не можешь ответить») проверяются тоже: формы множественного числа берутся из самой книги, поэтому «создай» ловится, если где-то есть «создайте». «Ты» допустимо только в прямой речи в кавычках — вопрос к ядру, чужая формулировка задачи.
- **Устоявшийся перевод**: если для слова в книге уже есть русский вариант (следующий узел, перечисление, оконечное устройство, райзер, экспандер, перехват, прошивка, плоскость управления), английский оригинал в прозе и в банке заданий считается ошибкой. Имена объектов и параметров (Endpoints, capture_output, firmware volume) — исключения, они перечислены рядом с правилом.
- **Работы практикума** делает один человек за одним стендом: «студент» и «учащийся» в описаниях работ L00–L36 запрещены (в экзаменационных рубриках ниже — нет).
- **Справочник терминов** (`public/reference-terms.json` плюс приложение C) обязан покрывать частые слова: латинское слово, встречающееся в прозе не реже десяти раз, должно иметь определение. Панель «Определение» — единственная помощь читателю, наткнувшемуся на незнакомое слово, а база успела отстать от текста: в ней были `pstore` и `Machine Check`, но не было VM, GiB, CPU и RTO. Проверка спрашивает **ту самую `defLookup` из `site.js`**, которой отвечает панель, а не разбирает термины сама: свой разбор засчитывал слово, встреченное частью составного термина, — «TCP» считался определённым через «TCP handshake», а панель на выделенное «TCP» отвечала «Определения нет». Так прошли мимо Linux, systemd, Python и Docker. Составные термины базы вычёркиваются из текста до подсчёта (иначе статья требовалась бы на каждое слово из «Secure Boot» и «Load average»), а подписи внешних ссылок прозой не считаются.
- **Политика безопасности**: страницы несут `Content-Security-Policy` в `<meta>` (заголовки GitHub Pages задать не даёт). Из-за этого атрибут `style="…"` и обработчик `onclick="…"` в разметке перестают работать — молча, без следа в разметке: выравнивание столбца просто пропадает. Выравнивание чисел в таблицах задаётся классом `num`. Хеши встроенных скриптов считаются по готовой странице (`sealPolicy` в генераторе, уже после подстановки `BASE_PATH`), поэтому политика не может разойтись с содержимым.
- **Скрипт, ищущий чужой элемент**: встроенный скрипт падает на первой же строке и уносит всё, что идёт ниже. Так на `/assessment/a1/` не работали все 40 вопросов: скрипт из `course.html` начинался с фильтра оглавления, которого на этой странице нет. Обращение к элементу с соседней страницы пишется через `?.`, иначе проверка не пропустит.
- **Автопроверка работ**: инжектор — единственное место в проекте, которое меняет чужую машину, поэтому у скрипта обязаны быть отказ без метки `/etc/course-lab-stand`, `restore`, `--dry-run` и неприкосновенная управляющая сеть; сбор фактов и вердикт разделены; ожидаемые значения в `lab-data` лежат только хешами; каждая работа ссылается только на существующие операции сверки и заведена в реестре `course_lab.py`; сверка по хешу требует самого хеша; текст работы лежит на той же странице; верные объяснения не стоят все на одном месте — тот же урок, что и с банком заданий. Результаты работ живут внутри ключа прогресса, поэтому переносятся вместе с ним; отдельный ключ пришлось бы вносить в `BACKUP_KEYS`.
- **Каркас главы**: вопрос до чтения стоит выше раздела N.1, свободное воспроизведение — до мини-тренажёра, темы воспроизведения начинаются неотмеченными, верный ответ тренажёра не печатается в разметку.
- **Вопросы мини-тренажёра не повторяют банк кабинета**: у каждой из 34 глав ровно два своих вопроса по четыре варианта с разбором, и ни один не совпадает по тексту с заданием банка. Верные ответы распределены по позициям — тот же урок, что и с банком.
- **Одно написание — одна статья справочника**: индекс панели («Определение») занимает ключ первым совпадением и молча отбрасывает второе. «mac» отвечал статьёй Ethernet вместо «MAC-адрес», «плейбук» — статьёй YAML вместо Ansible, а Timeout и «Тайм-аут» были двумя статьями об одном понятии, из которых читатель видел одну. Ни в сборке, ни в разметке это не видно: панель просто отвечает не тем. Повтор написания внутри одной статьи безвреден и правилом не ловится.
- **Перенос прогресса один на весь курс** и живёт на `/route/#route-backup`: он собирает все восемь ключей. Своя кнопка экспорта в кабинете уносила один ключ из восьми — мини-тренажёры глав, календарь, заметки и настройки чтения оставались в старом браузере, хотя файл выглядел полноценной копией. Кабинет только ведёт на «Маршрут» (адрес подставляется в `studyScript`, как и `#autopractice`).
- **Единственное число повелительного наклонения** ловится двумя способами: по паре из самой книги («создайте» → «создай») и по списку `ORDERS` в валидаторе. Список нужен потому, что глагол, употреблённый на «ты» один-единственный раз, пары в книге не имеет: «привяжи API к loopback» в лаборатории 22.14 пережило две вычитки и правило.

## Публикация

`.github/workflows/pages.yml` собирает и публикует при push в `main`; `BASE_PATH` он выбирает сам по имени репозитория. Действия закреплены хешами коммитов, а не тегами (тег можно передвинуть); номер версии стоит комментарием рядом, хеш берётся через `git ls-remote --tags`. Каталог `build/` в Git не хранится.
