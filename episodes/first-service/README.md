# Пробный эпизод «Свой сервис. Первое дежурство»

Эпизод начинается с вводного урока: зачем изучать инфраструктуру, что такое
сервис, как соотносятся запрос, ответ, браузер, программа и компьютер. Небольшой
опыт с приветствием показывает настоящий обмен запросом и ответом. Затем
разбирается конкретная задача — страница с личной заметкой. Прочитанное
сохраняется отдельно от практики. Урок можно открыть повторно через
`http://127.0.0.1:4180/workshop/?lesson=intro`; существующая заметка сохраняется.

Это начальный опыт курса серверной инфраструктуры. Его страница — удобная
нагрузка для наблюдения процесса и файла; итог всего курса — самостоятельная
инфраструктурная лаборатория, её диагностика, воспроизведение и восстановление.

Эксперимент с форматом самостоятельного обучения, ориентир — 30–40 минут. Учащийся
создаёт личную страницу, сохраняет свою запись и проверяет её после перезапуска.
Затем восстанавливает доступ через вход и решает похожую задачу с другой
ошибкой конфигурации. Гипотезы, наблюдения и короткий разбор сохраняются вместе
с фактическими ответами сервиса.

Запуск из корня репозитория (Node.js 22.13+):

```powershell
npm run episode
```

Открыть http://127.0.0.1:4180. На Windows можно дважды открыть `start.cmd` в этом
каталоге. Остановка — Ctrl+C в терминале. При повторном запуске страница и
прогресс восстанавливаются из `.episode-state/first-service/`. Запись хранится
в `note.json`, ход работы — в `progress.json`, конфигурация — в `service.json`
и `gateway.json`. Каталог исключён из Git.
Закрытие вкладки не останавливает сервис; остановка мастерской завершает её
дочерний процесс. Только один запуск может использовать один каталог данных.

Сервис действительно работает в отдельном процессе Node.js и слушает свой
локальный порт. Вход читает свою конфигурацию из файла и выполняет HTTP-запрос
к этому процессу. Ошибки 502
возникают из-за реального несовпадения портов. Это локальная лаборатория,
а не отдельная Linux-машина или проверка удалённой сети. Произвольные команды
ОС не исполняются: консоль содержит только явно перечисленные команды опыта.

В первом инциденте меняется порт сервиса, во втором — назначение входа.
Проверка принимает любое согласованное исправление и требует подтверждения
через вход. Свободное объяснение сохраняется без автоматической оценки смысла.
Завершение эпизода подтверждает выполнение опыта; сохранность навыка проверяют
позже новым вариантом. Кнопка повторения создаёт новый вариант, сохраняя
предыдущий разбор. Напоминаний и внешней отправки данных нет.

Проверка в настоящем Chromium:

```powershell
npm run episode:check
```

Она использует временный каталог и свободные порты, проходит вводный урок и все три этапа,
проверяет отрицательные исходы, восстановление прогресса после перезапуска,
выгрузку отчёта, мобильную ширину и добавление урока к уже существующей работе.
Нужны Playwright и Chromium, как для
существующего `scripts/smoke-browser.mjs`. Скриншоты остаются в
`work/episode-evidence/`. Данные учащегося тест не использует.

Для другого порта или каталога: `EPISODE_PORT` и `EPISODE_STATE_DIR`.
Сервер привязывается только к `127.0.0.1`; API принимает изменения лишь
с токеном текущего запуска. Экспорт содержит пользовательский текст и
локальный путь к записи — перед передачей можно прочитать JSON.
